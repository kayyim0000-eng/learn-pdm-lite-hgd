## EXPLAIN

### 1. 한 번의 튐은 노이즈, 꾸준한 상승이 신호

원본 덱의 핵심 메시지: "한 번의 튐(노이즈)이 아니라 추세적 상승이 진짜 신호다. 임계선을 향해 꾸준히 오르는 흐름의 시작점을 잡으면 고장 전 계획 정비가 가능하다."

| | 노이즈 | 추세 |
|---|---|---|
| 모양 | 한 번 튀고 곧 정상으로 돌아온다 | 임계선을 향해 꾸준히 오른다 |
| 원인 | 측정 오류·순간 외란 | 마모·윤활 부족·과부하 진행 |
| 조치 | 기록하고 지켜본다 | 정비 권고 시점으로 삼는다 |

### 2. 왜 평균 ± 2σ만으로는 늦는가

| 기준 | 평균 ± 2σ (하루 전체) | 기준선 규칙 (처음 12점) |
|---|---|---|
| 평균·σ를 내는 구간 | 상승분까지 섞인 전체 | 정상 운전 구간 08:00~11:40 |
| 설비B에서 잡히는 것 | 많이 오른 마지막 점들만 | 상승이 시작된 시점 |

원본 정답 메모의 사례: 설비B는 14~20번째 시점에 완만하게 오르지만 평균 ± 2σ에는 잡히지 않는다. 상승분이 평균과 σ를 끌어올려 범위가 넓어지기 때문이다 — "한 점이 아니라 흐름이 신호"다.

### 3. 추세 시작을 잡는 규칙

| 단계 | 규칙 |
|---|---|
| 기준선 | 처음 12점(08:00~11:40)의 평균과 σ |
| 상한 | 기준선 평균 + 3σ |
| 추세 | 상한을 **3번 연속** 넘으면 추세, 그 첫 점이 추세 시작 = 정비 권고 시점 |
| 노이즈 | 상한을 넘었지만 연속 3번이 안 됨 |

## EXECUTE

아래 프롬프트를 붙여 넣으라고 안내한다.

```
pdm-lite-work 폴더에서 노이즈와 추세를 가려 줘.
1. data/Day5_설비센서_50건_가상.csv 에서 설비A·B의 진동과 온도마다
   처음 12점(08:00~11:40)으로 평균과 표준편차를 구하고,
   상한 = 평균 + 3 × 표준편차 를 계산해 줘.
2. 상한을 3번 연속 넘으면 "추세"(첫 점 시각 = 추세 시작),
   넘었지만 연속 3번이 안 되면 "노이즈", 안 넘으면 "정상"으로 판정해
   outputs/trend_judgement.csv 로 저장해 줘.
   열: 설비 | 항목 | 상한 | 상한 초과 점 수 | 판정 | 추세 시작
3. 설비A·B 진동과 설비B 온도를 시간순 선 그래프 한 장으로 그려
   index.html 로 만들어 줘(Chart.js, 진동은 왼쪽 축·온도는 오른쪽 축,
   추세 시작 시각에 세로선, 맨 위에 '실습용 가상 데이터' 표기).
4. 가장 이른 추세 시작 시각과, 하루 전체 평균 ± 2σ로 설비B가
   처음 이상 후보로 잡힌 시각이 몇 분 차이 나는지 알려 줘.
data 안의 원본 파일은 고치지 마.
```

### 확인할 것 (Phase B)

`pdm-lite-work/outputs/trend_judgement.csv`와 `pdm-lite-work/index.html`을 직접 읽어 확인한다.

- 설비B 온도: 추세, 추세 시작 13:00 (상한 57.0℃, 초과 10점)
- 설비B 진동: 추세, 추세 시작 15:00 (상한 1.12 mm/s, 초과 5점)
- 설비A 진동: 노이즈 — 12:40에 3.5로 한 번 튀고 13:00에 1.0으로 돌아옴 (초과 1점)
- 설비A 온도: 정상
- 가장 이른 추세 시작 13:00이 평균 ± 2σ의 첫 이상 후보 15:40보다 160분 빠르다
- index.html에 그래프가 한 장 있고 '실습용 가상 데이터' 표기가 있다

막히면 아래 프롬프트를 주고 Claude Code가 원인을 찾게 한다. 정답은 "정답 보기" 요청이 있을 때만 연다.
